# JAC mouth live audio amplitude

The mouth animation prefers real audio amplitude (`getJacLiveAmplitude()` in `jac-audio-analyser.ts`) and falls back to the sine simulation when it returns null.

**Rules learned:**
- The analysis AudioContext must be created/resumed inside a real user gesture (hooked into `unlockAudioContext()` + capture-phase pointerdown/keydown). The `playing` event of ElevenLabs' WebRTC `<audio>` element is NOT gesture-authorized on iOS Safari — resuming there fails silently.
- **Why:** gesture-gated browsers reject `resume()` outside interaction; a suspended context makes the tap read nothing and the mouth silently stays on simulation.
- Chromium quirk: a `MediaStreamAudioSourceNode` analysing a stream generated by *another* AudioContext (`createMediaStreamDestination`) reads silence. Real remote WebRTC streams work — so e2e tests must use an RTCPeerConnection loopback, not a raw local synth stream. Also connect the analyser through a 0-gain sink to destination so the graph is pulled.
- WebRTC loopback audio takes ~1–2 s to start flowing; e2e sampling must poll several seconds, not a fixed 600 ms window.

**How to apply:** any future audio-visualization work (listening glow from mic level, etc.) should reuse `registerJacAnalyser`/`unlockJacAnalyserContext` and test via the loopback pattern in `e2e/jac-mouth-live-amplitude.spec.ts`.
